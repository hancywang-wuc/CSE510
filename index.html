COURSE DESCRIPTION

Operating system (OS) is a set of system software programs in a computer that regulate the ways application software programs use the computer hardware and the ways that users control the computer.

This class introduces the facilities provided in modern operating systems. Topics include: principles of operating system design and implementation; concurrent processes; inter-process communication; job and process scheduling; deadlock handling; issues in memory management (virtual memory, segmentation, paging); and auxiliary storage management (file systems, directory structuring, protection mechanisms); performance issues; and case studies.

LEARNING OBJECTIVES

This course examines the important concerns in operating system design and implementation. An operating system provides an established, convenient, and efficient interface between user programs and the executing hardware. Such an operating system is responsible for resources management (e.g., disks, networks, and processors), providing common services required by many different programs (e.g., file service, the ability to start or stop processes, and access to the printer), and protecting individual programs from interfering with one another. The course will start with a brief historical perspective of the evolution of operating systems over the last fifty years and then cover the major components of most operating systems. This discussion will cover the tradeoffs that can be made between performance and functionality during the design and implementation of an operating system. Particular emphasis will be given to three major OS subsystems: process management (processes, threads, CPU scheduling, synchronization, and deadlock), memory management (segmentation, paging, swapping), and file systems; and on operating system support for distributed systems.

COURSE PROJECT

Title: Ubuntu Server — Full Desktop Configuration & Deployment

Objective: Configure, manage, and demonstrate a fully operational Ubuntu server using only the graphical desktop interface and mouse-driven controls — no commands, no code, and no copy-pasting at any point in the course. Each student works on their own school-provided Ubuntu server. Each week adds one new capability to the same server so that by Week 15 the server has a fully organized file system with correct permissions, a live web server, a structured database with multiple tables, a scheduled automated backup system, and a complete system image ready for deployment. The Week 15 final demonstration shows all of these capabilities working together on the live server.

Tools:

  • Ubuntu Desktop — the operating system and graphical interface used for all server configuration throughout the course

  • Ubuntu Software Centre — graphical application installer used to add and remove software from the server

  • System Monitor — built-in Ubuntu application for viewing real-time CPU, memory, and process information

  • Files app — built-in Ubuntu file manager used for all folder and file management

  • System Settings — built-in Ubuntu control panel for network, users, firewall, power, and display configuration

  • GUFW — graphical firewall manager available from the Ubuntu Software Centre

  • Apache/Python Web Server — installed from the Ubuntu Software Centre or simply command lines; serves the web server demonstration page

  • DB Browser for SQLite — visual database tool available from the Ubuntu Software Centre; used to create and manage databases without writing code

  • Ubuntu Backups (Deja Dup) — built-in Ubuntu backup application for scheduling and managing automated file backups

  • Disks utility — built-in Ubuntu tool for creating and restoring full system images

  • Claude (claude.ai) or ChatGPT (chatgpt.com) — AI assistant that explains every operating system concept in plain English and guides students through each configuration decision

Deliverables:

  • Configured Ubuntu Desktop with an organized application dock and a structured folder hierarchy with correct read/write permissions on each folder

  • System resource review: identified and documented the top CPU and memory consumers on the server using the System Monitor

  • Installed and removed applications using the Software Centre, with evidence of clean uninstallation

  • Network configuration: static IP address set and firewall rules configured using the graphical firewall manager

  • User accounts: administrator and standard accounts created with correct privilege levels

  • Live web server: Apache installed and serving a locally hosted web page accessible via Firefox

  • Database: DB Browser for SQLite database with two tables populated with sample data and filtered views demonstrated

  • Automated backup: scheduled backup configured and verified, with a file successfully restored from backup

  • System image: complete partition image created using the Disks utility and stored on external media

  • Deployment (knowledge only) : system image successfully restored onto a fresh virtual disk with all original configuration intact

  • Full OS installation (knowledge only) : complete Ubuntu installation performed from scratch using the visual installer

Stretch Goals (Extra Credit):

WEEKLY COURSE OUTLINE & TIMETABLE

DATE TOPICS
WEEK 1

System Anatomy — Understanding the Ubuntu Desktop

Students are introduced to the Ubuntu Desktop operating system for the first time. Each student is provided with their own Ubuntu server by the school and accesses it directly through the desktop graphical interface. Using only the mouse, students explore the desktop environment and identify its key components: the taskbar, the application dock, the file manager, the system settings panel, and the software center. Claude explains in plain English what an operating system is, the difference between hardware and software, and what role Ubuntu plays in connecting the two. By the end of this session, students have familiarized themselves with the desktop layout and customized the dock with the core applications that will be used throughout the course.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://documentation.ubuntu.com/desktop/en/latest/tutorial/install-ubuntu-desktop/

Weekly Assignment: Log in to your school-provided Ubuntu server or any OS like iPhone/Android phone. Using only the mouse/Tap/Touchscreen, customize the desktop/home screen dock to include any apps related to Files app, Firefox browser, Software Centre, System Settings, System Monitor, and Text Editor. Screenshot the customized dock and the full desktop. Submit to Moodle. This desktop configuration will be used as the starting point for every session that follows.

Note: Using alternative OS to show case the similar concepts apply to all future weekly assignments.
WEEK 2

File Management & Folder Permissions

Students learn how the Ubuntu operating system organizes data into a hierarchy of folders and controls which user accounts are allowed to read, write, or open each one. Using the Files app, students explore the Ubuntu directory structure — understanding the purpose of key folders such as Home, Documents, and the system directories visible in the file manager sidebar. Students create a structured folder organization for their server work, then use the graphical Properties panel to set permissions on each folder, restricting access where appropriate. Claude explains what each permission level means and why controlling folder access is a fundamental responsibility of any operating system.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://pages.cs.wisc.edu/~remzi/OSTEP/file-intro.pdf

Weekly Assignment: Using the Files app, create a folder structure inside the Home directory with three subfolders: Server Projects, Shared Files, and Private Config. Right-click each folder, open Properties, go to the Permissions tab, and set appropriate access levels for each — Private Config should be owner-only. Screenshot the folder structure in the Files app and the permission settings for each folder. Submit to Moodle.

Hands-on Experiment: Permission test: In System Settings, create a second standard user account. Log in as that user and attempt to open the Private Config folder. Screenshot the access denied result. Log back in as the main administrator account. Write one sentence explaining why restricting folder access is an essential operating system function.

Note: Alternative OS option — On an iPhone, use the Files app to create folders under On My iPhone and use the Share sheet to see how access is limited between apps. On Android, use the Files app to create folders and check Settings > Apps > Permissions to see how each app's storage access is individually restricted, mirroring the concept of folder permissions.
WEEK 3

Monitoring System Resources — CPU, Memory & Running Processes

Students open the System Monitor application and observe in real time how Ubuntu distributes processing power and memory across all currently running programs. Students learn to read the CPU usage and memory consumption graphs, identify which applications are consuming the most resources, and use the graphical End Process button to close unnecessary background processes. Claude explains what CPU usage and memory allocation mean in the context of a server, what happens when available resources are exhausted, and why a system administrator needs to monitor resource usage regularly.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-intro.pdf

Weekly Assignment: Open the System Monitor. Identify the three processes consuming the most CPU and the three consuming the most memory. Screenshot the System Monitor with those processes visible and their resource usage readable. Identify at least one non-essential background process and end it using the End Process button. Screenshot the updated process list after closing it. Submit both screenshots to Moodle.

Hands-on Experiment: Resource stress test: Open ten browser tabs in Firefox simultaneously and observe how the CPU and memory graphs respond in the System Monitor. Screenshot the graphs at peak usage, then close all tabs and screenshot them again once they settle. Write one sentence explaining the relationship between the number of active applications and the server's available resources.

Note: Alternative OS option — On an iPhone, check Settings > Battery and Settings > General > iPhone Storage to see which apps use the most battery and storage, then swipe up on an app in the App Switcher to force-close it. On Android, check Settings > Battery and Settings > Storage (or Device Care) to identify the top resource-consuming apps, then force-stop one from Settings > Apps.
WEEK 4

Installing & Removing Software Using the Software/App Centre

Students learn how Ubuntu manages application installation through the Software Centre — a graphical application store that handles the entire process automatically. Students install a visual text editor for editing server configuration files and a file archiving tool for compressing and extracting files. Students also practice removing an application they no longer need. Claude explains what happens inside the operating system when software is installed — how Ubuntu locates the correct package, resolves dependencies, places files in the right locations, and registers the application — all without the student needing to interact with anything other than the Software Centre interface.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://documentation.ubuntu.com/desktop/en/latest/how-to/software/

Weekly Assignment: Open the Ubuntu Software Centre. Install a visual text editor (such as Gedit or Kate) and a file archive manager (such as File Roller). Confirm both applications appear in the application menu and open correctly. Then uninstall one of them through the Software Centre. Screenshot the Software Centre showing the installation of each app and the uninstall confirmation. Submit to Moodle.

Hands-on Experiment: Software removal test: After uninstalling one application, check the application menu to confirm it no longer appears. Try to open it from the Files app if any leftover files remain. Screenshot the result. Write one sentence explaining why the operating system needs to cleanly remove all associated files when an application is uninstalled.

Note: Alternative OS option — On an iPhone, use the App Store to install an app, then press and hold the icon and choose Remove App to uninstall it. On Android, use the Google Play Store to install an app, then uninstall it from Settings > Apps or directly from the Play Store listing, observing the same install/uninstall cycle as the Ubuntu Software Centre.
WEEK 5

Exploring the System Settings — The Operating System Control Panel

Students explore the Ubuntu System Settings panel in depth — the central graphical interface for configuring the operating system's core behavior. Students work through each major settings category: display and resolution, power management, default applications, accessibility options, region and language, and the privacy settings that control what the operating system logs and retains. Claude explains what each settings category controls inside the operating system and why these configurations matter for a server that is expected to run reliably without interruption.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://documentation.ubuntu.com/desktop/en/latest/how-to/accessibility/#

Weekly Assignment: Open System Settings and complete the following configurations using only the mouse: set the display to the highest available resolution, disable automatic screen lock in Privacy settings, set the power profile to Performance, and confirm the correct region and language settings. Screenshot each settings panel after making the change. Submit all screenshots to Moodle.

Hands-on Experiment: Settings impact test: In System Settings, temporarily enable automatic screen lock with a 1-minute timeout. Wait for the screen to lock, then unlock it. Then disable automatic screen lock again. Screenshot the lock screen and the disabled setting. Write one sentence explaining why an unattended server should not automatically lock its screen during active use.

Note: Alternative OS option — On an iPhone or Android phone, open the Settings app and work through the equivalent categories: Display & Brightness, Battery, Default Apps, Accessibility, Language & Region, and Privacy. Screenshot each panel the same way as the Ubuntu System Settings exercise.
WEEK 6

Network Configuration & Firewall Management

Students configure the Ubuntu server's network settings using the System Settings Network panel and manage the firewall using the graphical Firewall application available in the Software Centre. Students view the server's current IP address, configure a static IP address using the graphical network editor, and use the firewall interface to enable the firewall and configure rules that allow only specific types of network traffic. Claude explains in plain English what an IP address is, what a firewall does, and what a network port is — using clear, non-technical language throughout.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://documentation.ubuntu.com/desktop/en/latest/tutorial/the-linux-command-line-for-beginners/

Weekly Assignment: Open System Settings and navigate to the Network panel. Record the server's current IP address and screenshot the network configuration screen. Install the GUFW graphical firewall manager from the Software Centre. Enable the firewall and add rules to allow web traffic (HTTP and HTTPS). Screenshot the firewall panel with the rules active and the firewall enabled. Submit to Moodle.

Note: Alternative OS option — On an iPhone, go to Settings > Wi-Fi and tap the (i) next to your network to view the IP address, then explore Screen Time > Content & Privacy Restrictions as a simplified parallel to firewall rules. On Android, go to Settings > Network & Internet > Wi-Fi to view the IP address, then explore Digital Wellbeing or a firewall app such as NetGuard to allow or block traffic by app.
WEEK 7

User Account Management

Students manage user accounts on the Ubuntu server using the System Settings Users panel. Students create two new user accounts — one with administrator privileges and one as a standard user — set secure passwords for each, and configure display names. Students then review the full list of accounts, identify which ones have administrator access, and understand the difference between what each type of account can and cannot do on the server. Claude explains why controlling who has administrator access is one of the most important security responsibilities of a server administrator.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://documentation.ubuntu.com/desktop/en/latest/tutorial/the-linux-command-line-for-beginners/

Weekly Assignment: Open System Settings and navigate to the Users panel. Create an administrator account named Server Admin and a standard account named Server User. Set a secure password for each. Screenshot the Users panel showing both accounts with their respective privilege levels visible. Submit to Moodle.

Hands-on Experiment: Privilege comparison: Log in as the Server User standard account. Attempt to open System Settings and navigate to the Users panel to create a new account. Screenshot the result — whether it is blocked or requires a password. Log back in as the administrator. Write one sentence explaining why the operating system enforces different permission levels for different user accounts.

Note: Alternative OS option — iPhones do not support separate user accounts, so this concept is best explored on Android: go to Settings > System > Multiple Users, add a new restricted user, and compare what that account can and cannot access versus the primary administrator account. iPhone users can approximate this using Screen Time > Family Sharing to review parental and restricted access controls.
WEEK 8

Enabling the Web Server & Hosting a Local Web Page

Students install the Apache web server from the Ubuntu Software Centre and configure it to serve a locally hosted web page. Using the Files app, students navigate to the web server's root folder and place a simple HTML file — generated by Claude — into it. Students then open Firefox and confirm the web page is accessible by navigating to the server's own IP address. Using the System Monitor, students observe the Apache web server process running alongside the operating system's other processes. Claude explains what a web server does, how it receives requests from browsers, and how the operating system handles the network connection between them.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://httpd.apache.org/docs/2.4/

Weekly Assignment: Install Apache from the Ubuntu Software/App Centre or through embedded python module. Open the Files app and navigate to the folder want to publish (e.g. /var/www/html/ for Apache). Place Claude's generated HTML file into the folder.
Open Firefox and navigate to http://localhost to confirm the web page loads. Screenshot the browser showing the live page and the System Monitor showing the Apache/Python process running. Submit to Moodle.

Hands-on Experiment: Web server on/off test: Use the System Monitor to find and end the Apache process. Refresh the browser and screenshot the result — the page should no longer load. Restart Apache using the Software Centre's manage application feature. Confirm the page loads again. Write one sentence explaining the relationship between a running operating system process and a service that users can access.

Note: Alternative OS option — Phone operating systems sandbox apps and do not allow a true self-hosted web server the way Ubuntu does. Students without access to the Ubuntu server may instead install a simple local HTTP server app from the Play Store to serve a basic page on the local network, or review the concept with Claude/ChatGPT and screenshot the app's running state as a substitute for the live Apache demonstration.
WEEK 9

Introduction to Databases — Creating & Managing Data Visually

Students install DB Browser for SQLite from the Ubuntu Software Centre — a fully graphical database tool that allows students to create and manage databases without writing any code or queries. Students create a new database file, define their first table using the visual table designer, and add columns with appropriate data types using only dropdown menus and text fields. Students then insert rows of sample data using the graphical row editor and use the visual browse and filter controls to search the data. Claude explains what a database is, how it differs from a folder of files, and why servers use databases to store structured information.

AI Tools: Claude of ChatGPT

Reading Assignment (6 hrs): https://github.com/sqlitebrowser/sqlitebrowser/wiki

Weekly Assignment: Install DB Browser for SQLite from the Ubuntu Software Centre. Create a new database file named server_data.db. Use the visual table designer to create a table named User Accounts with columns for Username (text), Role (text), Email (text), and Date Created (text). Add at least five rows of sample data using the graphical row editor. Screenshot the completed table with all rows visible. Submit to Moodle.

Note: Alternative OS option — On an iPhone or Android phone, install a lightweight SQLite database app from the App Store or Play Store (search “SQLite viewer” or “SQLite editor”) to create a table and add sample rows, mirroring the DB Browser exercise. Alternatively, use the Numbers or Google Sheets app to build a structured table as a simplified stand-in for rows and columns.
WEEK 10

Expanding the Database — Adding Tables & Filtering Data

Students expand the server database by adding a second table using DB Browser for SQLite's visual table builder. Students define a Server Activity Log table to record events on the server, then use the graphical filter, sort, and search controls to locate specific records without writing any code. Students also explore the relationship between the two tables using DB Browser's visual schema diagram. Claude explains how databases with multiple related tables reflect how real servers store and organise different types of information, and how the web server from Week 8 could eventually retrieve and display this data.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://github.com/sqlitebrowser/sqlitebrowser/wiki/Using-the-Filters

Weekly Assignment: Open DB Browser for SQLite and add a second table to the server_data.db database named Activity Log with columns for Event ID, Username, Action, and Timestamp. Add at least five rows of sample log entries. Use the visual filter controls to display only the entries belonging to one specific username. Screenshot the filtered result and the schema diagram showing both tables. Submit to Moodle.

Hands-on Experiment: Data integrity test: In DB Browser, attempt to add a new row to the Activity Log table while leaving the Username column empty. Observe what happens. Then use the table designer to set the Username column as required (NOT NULL). Attempt the empty row again and screenshot the result. Write one sentence explaining why preventing empty required fields is important for maintaining reliable server records.

Note: Alternative OS option — Using the same mobile SQLite app from Week 9 (or a spreadsheet app), add a second table or sheet, enter sample log-style data, and use the app's built-in search or filter feature to isolate records belonging to one user, mirroring the filtering exercise in DB Browser.
WEEK 11

Backup & Data Protection

Students configure the Ubuntu Backups application (Deja Dup) to automatically save all server project files and the database to an external storage location on a scheduled basis. Students run a manual backup immediately, verify the backup files have been created correctly, and then simulate a data loss scenario by deleting a project file and restoring it from the backup. Claude explains the difference between a file backup and a full system snapshot, what is permanently lost when a server fails without a backup, and why automated scheduled backups are a minimum safety standard for any server storing important data.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://apps.gnome.org/DejaDup/

Weekly Assignment: Open the Backups application. Configure it to back up the Home directory and Server Projects folder to an external drive or secondary storage location. Schedule automatic backups daily. Run a manual backup immediately and confirm the backup files appear in the destination. Delete one file from the Server Projects folder, then use the Backups app to restore it. Screenshot the backup configuration, the successful backup, and the restored file. Submit to Moodle.

Note: Alternative OS option — On an iPhone, confirm iCloud Backup is enabled in Settings > [Your Name] > iCloud > iCloud Backup, run a manual backup, delete a note or photo, and restore it from Recently Deleted. On Android, confirm Google backup is enabled in Settings > System > Backup, run a manual backup, then restore a deleted item from Google Photos Trash or the relevant app's recycle bin.
WEEK 12

Creating a Full System Image

Students use the Ubuntu Disks utility to create a complete image of the server's current state — capturing the operating system, all installed applications, configuration settings, and data files in a single image file saved to an external drive. This system image represents a full snapshot of everything that has been built and configured over the first eleven weeks of the course. Claude explains the difference between a file backup and a system image, when each is appropriate, and how system images are used in professional server environments to standardize deployments and enable rapid disaster recovery.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://help.ubuntu.com/stable/ubuntu-help/disk-partitions.html.en

Weekly Assignment: Open the Disks utility. Select the main system drive. Use the gear icon menu to create a partition image and save it to an external drive. Confirm the image file appears on the external drive in the Files app. Screenshot the Disks utility during the image creation process and the resulting image file with its file size visible. Submit to Moodle.

Hands-on Experiment: Image size analysis: Right-click the system image file in the Files app and view its properties to find its size. Compare this to the total size of just the Home directory. Ask Claude to explain what the difference in size tells you about what a system image contains versus a file backup. Write one sentence summarizing the key difference.

Note: Alternative OS option — On an iPhone, connect to a computer and use Finder (or iTunes) to create a full encrypted backup, which functions like a system image. On Android, use the manufacturer's backup tool or Google's full device backup (Settings > System > Backup) to capture a complete device snapshot, then compare its size to a single folder's size as in the Week 12 experiment.
WEEK 13

Restoring from a System Image — Server Deployment

Students restore the Week 12 system image onto a fresh virtual disk using the Disks utility's Restore Partition Image function. This simulates the real-world process of deploying a fully configured server onto new hardware — a task that server administrators perform when replacing failed hardware, scaling to additional machines, or setting up identical server environments across multiple locations. After restoring, students verify that all previously configured settings, installed applications, and saved files are intact and working on the restored disk. Claude explains why restoring from a system image is faster and more reliable than rebuilding a server manually from scratch.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://help.ubuntu.com/stable/ubuntu-help/disk-partitions.html.en

Weekly Assignment: Open the Disks utility and attach a secondary virtual disk. Use the Restore Partition Image option to deploy the Week 12 system image onto the new disk. Boot from the restored disk and confirm the following are all intact: the desktop dock configuration from Week 1, the folder structure from Week 2, the Apache web page from Week 8, and the database from Week 9. Screenshot all four confirmations on the restored disk. Submit to Moodle.

Note: Alternative OS option — If a spare or reset iPhone/Android device is available, restore the Week 12 full-device backup onto it and confirm installed apps, settings, and files return successfully, mirroring the Disks utility restore exercise. If no spare device is available, discuss with Claude/ChatGPT what would be restored and screenshot the backup's file list as evidence of its scope.
WEEK 14

Full Ubuntu Server Installation Using the Visual Installer

Students perform a complete, fresh installation of Ubuntu Server using the school-provided installation media and the Ubuntu visual setup wizard or install onto student’s laptop as needed. Students work through each screen of the installer using only the mouse: selecting language and keyboard layout, choosing the installation disk, setting the time zone on the visual map, creating the initial administrator account, and completing the installation. This session teaches students what the operating system installation process involves at each step, preparing them to set up a server from scratch whenever required. Claude walks students through what each installer screen is asking and what each choice means before they click.

AI Tools: Claude or ChatGPT

Reading Assignment (6 hrs): https://documentation.ubuntu.com/desktop/en/latest/tutorial/install-ubuntu-desktop/

Weekly Assignment: Using the school-provided installation media, complete a full Ubuntu installation on a designated practice disk or virtual machine. Work through every installer screen using only the mouse. After installation, confirm the system boots to the desktop successfully. Screenshot each major installer screen — language selection, time zone configuration, disk setup, and user account creation — as well as the final working desktop after installation. Submit all screenshots to Moodle.

Note: Alternative OS option — With Claude or ChatGPT guiding each step, perform a full factory reset and fresh setup on a personal iPhone or Android phone: language and region selection, Wi-Fi connection, account sign-in, and initial configuration. Screenshot each major setup screen just as with the Ubuntu visual installer. This is optional and only recommended if a spare or resettable device is available.
WEEK 15 Final Review/makeup for the weekly submissions and Q/A Session

The alternative OS (iPhone/Android) options in Weeks 1-14 assignments will be reviewed. All the previous Week 1-14 compiles the capstone project and will be reviewed and discussed live in class and provide Q/A session to support the students altogether.

ACADEMIC DISHONESTY AND PLAGIARISM

  1. Identification of Resources

It is important for students to properly cite all resources used to complete classwork. Homework plagiarism is a form of academic dishonesty. Assignment plagiarism may include any of the following:

  1. Copying text verbatim without proper citation.

  2. Using data without citing sources.

  3. Unauthorized use of other people's information or ideas.

  1. Seeking Clarification

If students have any questions about these forms of plagiarism or the assignments they are preparing, they should ask their instructor for clarification rather than risking academic dishonesty.

  1. Cheating & Plagiarism

It is essential for students to maintain honesty and trustworthiness. Work submitted for examinations or other forms of assessment must represent the individual's own work, knowledge, and experience on the subject. Students are required to follow the classroom rules set by the instructor. Cheating may include any of the following:

  1. Unauthorized viewing or obtaining information from any unauthorized source, including another student's work or any material that will be graded during an examination.

  2. Unauthorized obtaining, reading, or studying of exam questions before the scheduled exam date and time.

  3. Altering any part of a graded exam or report and resubmitting it as original work to be regraded.

  4. Misrepresenting work as your own to receive a grade or score.
